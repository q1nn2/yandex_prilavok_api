# БР-22 — PUT /api/v1/orders/{id} возвращает 409 Conflict вместо ошибки валидации при невалидном типе quantity

- **Приоритет:** Major
- **Статус:** Open

## Предусловия

Создать набор:

curl --location --request PUT 'https://b9c52f5b-aed7-4de2-a78b-69c29b57eb0d.serverhub.praktikum-services.ru/api/v1/orders/66' \
--header 'Content-Type: application/json' \
--data '{
  "productsList": [
    {
      "id": 1,
      "quantity": "12"
    }
  ]
}'

## Шаги воспроизведения

1. Отправить PUT-запрос на /api/v1/orders/{id}.
2. В path-параметр id передать id существующей корзины.
3. В body передать productsList с невалидным типом quantity: 
   строка "12", 
   "Один", 
   "one", 
    спецсимволы "@!",
    массив [1,2,3], 
     объект {} 
     большое значение 9999999999.
4. Нажать Send.

## ОР

Сервер возвращает 400 Bad Request с понятным сообщением о некорректном типе или значении quantity.

## ФР

Сервер возвращает 409 Conflict, хотя ошибка связана не с конфликтом склада, а с некорректным значением quantity.

## Комментарий

{
    "code": 409,
    "message": "Нет склада, способного обработать Ваш заказ"
}
